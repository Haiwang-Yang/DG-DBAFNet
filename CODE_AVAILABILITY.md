# Code Availability Statement

## Recommended Honest Wording

The experimental code has been organized into a release-ready repository. During peer review, the repository can be provided through a restricted or anonymized reviewer link if required by the journal. The full public repository, including source code, environment instructions, experiment configurations, and dataset split manifests, will be released upon acceptance/publication.

Raw audio recordings are not redistributed in the code repository. Users should obtain CTIS, ChMusic, and FolkMusic from their original sources and arrange them according to the documented directory structure.

## Safer Options

Option A: private reviewer repository.

Give editors/reviewers access during review, then switch the repository to public after acceptance.

Option B: anonymous reviewer archive.

Use an anonymized archive or OSF/Zenodo-style private view link if the journal allows anonymous review.

Option C: public minimal repository plus delayed full release.

Publicly provide method code skeleton, README, environment, and split-file documentation now, then release full runnable code after acceptance. The manuscript should state this limitation clearly.

## Avoid

Do not state that code and splits are fully public if the uploaded repository is deliberately incomplete. That creates a consistency problem during review.
